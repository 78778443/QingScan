# 工具回调方案设计

## 一、核心思路

- 系统只负责**启动任务**和**接收回调**
- 插件负责**执行逻辑**和**回调通知**

```
┌─────────┐    启动命令     ┌─────────┐
│  系统   │ ───────────────→│  插件   │
│         │   task_id       │         │
│         │   target        │         │
└────┬────┘                 └────┬────┘
     ↑                           │
     │      回调API              │
     └───────────────────────────┘
        - 状态更新
        - 结果提交
```

---

## 二、插件配置结构

插件只需要配置两个字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| `start_command` | 启动命令模板 | `python3 {script_path} --task-id={task_id} --target="{target}"` |
| `script_code` | 脚本代码（**Base64编码**存储） | `IyEvdXNyL2Jpbi9lbnYgcHl0aG9uMwo...` |

### 配置示例

```json
{
  "tool_name": "sqlmap",
  "start_command": "python3 {script_path} --task-id={task_id} --callback={callback_url} --target=\"{target}\"",
  "script_code": "IyEvdXNyL2Jpbi9lbnYgcHl0aG9uMwoiIiIKU1FMTWFwIFNRTO..."
}
```

**注意：** `script_code` 字段存储的是 Base64 编码后的脚本代码。运行时系统会自动解码并写入磁盘执行。

### 存储方式

```php
// 存储时编码
$scriptCode = base64_encode($rawScript);

// 运行时解码
$rawScript = base64_decode($tool->script_code);
file_put_contents($scriptPath, $rawScript);
```

### 支持的变量

| 变量 | 说明 |
|------|------|
| `{task_id}` | 任务ID |
| `{target}` | 扫描目标 |
| `{callback_url}` | 回调API地址 |
| `{script_path}` | 脚本写入后的路径（运行时生成） |

### 执行流程

```
1. 从数据库读取 script_code
2. 写入到临时文件 /tmp/scan_{task_id}/runner.py
3. 替换 start_command 中的 {script_path}
4. 执行命令
```

## 三、回调API设计

### 3.1 状态更新接口

**POST** `/api/callback/status`

请求体：
```json
{
  "task_id": 123,
  "status": "running",
  "progress": 50,
  "message": "正在注入测试..."
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| task_id | int | 是 | 任务ID |
| status | string | 是 | 状态：running/completed/failed |
| progress | int | 否 | 进度 0-100 |
| message | string | 否 | 状态消息 |

### 3.2 结果提交接口

**POST** `/api/callback/result`

请求体：
```json
{
  "task_id": 123,
  "status": "completed",
  "results": [
    {
      "vuln_type": "sqli",
      "vuln_level": "high",
      "vuln_url": "http://example.com?id=1",
      "vuln_title": "SQL注入",
      "vuln_detail": "存在基于布尔的盲注",
      "vuln_request": "GET /?id=1' HTTP/1.1",
      "vuln_response": "",
      "vuln_evidence": "参数id存在注入点"
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| task_id | int | 是 | 任务ID |
| status | string | 是 | 完成状态：completed/failed |
| message | string | 否 | 失败时的错误信息 |
| results | array | 否 | 漏洞结果列表 |

### 3.3 结果字段规范

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| vuln_type | string | 是 | 漏洞类型：sqli/xss/rce/lfi/... |
| vuln_level | string | 是 | 漏洞等级：critical/high/medium/low/info |
| vuln_url | string | 是 | 漏洞URL |
| vuln_title | string | 否 | 漏洞标题 |
| vuln_detail | string | 否 | 漏洞详情 |
| vuln_request | string | 否 | 请求包 |
| vuln_response | string | 否 | 响应包 |
| vuln_evidence | string | 否 | 证据 |

## 五、系统流程

### 5.1 启动任务

```php
<?php
// 1. 创建临时目录
$scriptDir = "/tmp/scan_{$task->id}";
if (!is_dir($scriptDir)) {
    mkdir($scriptDir, 0755, true);
}

// 2. 写入脚本到磁盘
$scriptPath = "{$scriptDir}/runner.py";
file_put_contents($scriptPath, $tool->script_code);
chmod($scriptPath, 0755);

// 3. 构建启动命令
$callbackUrl = config('app.url') . '/api/callback';
$command = str_replace(
    ['{task_id}', '{target}', '{callback_url}', '{script_path}'],
    [$task->id, escapeshellarg($task->target), $callbackUrl, $scriptPath],
    $tool->start_command
);

// 4. 后台执行
$process = new Process($command);
$process->setWorkingDirectory($scriptDir);
$process->start();

// 5. 更新任务状态
$task->update(['status' => 'running']);
```

### 5.2 接收回调

```php
<?php
// 状态更新
public function updateStatus(Request $request)
{
    $task = ScanTask::findOrFail($request->task_id);

    $task->update([
        'status' => $request->status,
        'progress' => $request->progress ?? 0,
    ]);

    return response()->json(['success' => true]);
}

// 结果提交
public function submitResult(Request $request)
{
    $task = ScanTask::findOrFail($request->task_id);

    // 保存结果
    foreach ($request->results ?? [] as $result) {
        ScanResult::create([
            'task_id' => $task->id,
            ...$result
        ]);
    }

    // 更新任务状态
    $task->update([
        'status' => $request->status,
        'progress' => 100,
    ]);

    return response()->json(['success' => true]);
}
```

## 六、插件开发规范

插件开发者需要遵循以下规范：

### 6.1 启动参数

插件必须支持以下命令行参数：
- `--task-id`: 任务ID
- `--callback`: 回调地址
- `--target`: 扫描目标

### 6.2 回调时机

1. **启动后**：调用状态更新接口，status=running
2. **执行中**：可定期调用状态更新接口更新进度（可选）
3. **完成后**：调用结果提交接口，提交最终结果

### 6.3 插件示例

```python
#!/usr/bin/env python3
import argparse
import requests
import json

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument('--task-id', required=True)
    parser.add_argument('--callback', required=True)
    parser.add_argument('--target', required=True)
    args = parser.parse_args()

    task_id = args.task_id
    callback = args.callback
    target = args.target

    # 1. 启动回调
    requests.post(f"{callback}/status", json={
        "task_id": task_id,
        "status": "running",
        "progress": 0,
        "message": "开始扫描"
    })

    try:
        # 2. 执行扫描逻辑
        results = do_scan(target)

        # 3. 进度更新（可选）
        requests.post(f"{callback}/status", json={
            "task_id": task_id,
            "status": "running",
            "progress": 50,
            "message": "扫描进行中"
        })

        # 4. 提交结果
        requests.post(f"{callback}/result", json={
            "task_id": task_id,
            "status": "completed",
            "results": results
        })

    except Exception as e:
        # 5. 失败回调
        requests.post(f"{callback}/result", json={
            "task_id": task_id,
            "status": "failed",
            "message": str(e)
        })

def do_scan(target):
    # 实际扫描逻辑
    return [
        {
            "vuln_type": "sqli",
            "vuln_level": "high",
            "vuln_url": target,
            "vuln_title": "SQL注入",
            "vuln_detail": "测试发现存在注入点"
        }
    ]

if __name__ == '__main__':
    main()
```

## 九、总结

这个方案的核心优势：

1. **极简**：系统只管启动和接收，不关心插件内部逻辑
2. **解耦**：插件完全自治，可使用任意语言/框架开发
3. **灵活**：插件自己决定何时更新状态、如何解析结果
4. **易管理**：脚本代码存数据库，无需维护额外文件

### 核心流程

```
启动任务 → 写入脚本到磁盘 → 执行命令 → 插件回调 → 接收结果
```
